## 一、结论速览

| 环节 | 状态 | 证据 |
|---|---|---|
| 官方解包工具可用 | ✅ | `XRCatTool.exe`；另用 Python 直读 `.cat/.dat`（46.1 万文件索引，随机读取） |
| NPC 替换机制明确 | ✅ | macro → component → 三个 mesh 槽位 |
| 材质/贴图自定义 | ✅ | `libraries/material_library.xml` 增加 collection |
| 骨骼兼容（最关键） | ✅ | 91 根骨，名称**顺序完全一致**，绑定数据**逐字节相同** |
| 模型来源可追溯 | ✅ | XAC 内部保留源工程文件名与导出器版本 |
| 模型导出器 | ⚠️ 外部依赖 | `X4CharacterConverter v0.8.7`（Nexus 2152，需登录） |

**一句话**：X4 的 NPC 替换是「**换网格、留骨架**」。只要新模型的骨骼表与原版逐字节一致，它就能直接吃下游戏共享的全套动画，不需要写任何脚本。参考 mod 正是这么做的。

## 二、NPC 替换的完整机制链

### 2.1 三层结构

```
charactergroups.xml   （按职业/性别注册"可选外观池"）
        ↓  引用
character_macros.xml  （macro：定义 head / torso / props 三个 mesh 槽位）
        ↓  引用
.xac 网格文件          （真正的模型）
        +
material_library.xml  （collection.material → 贴图绑定）
```

原生条目（`libraries/character_components.xml` 第 8788 行起）定义了所有 Argon 女性 NPC
**共享**的 `character_argon_female_01` component：

```xml
<component name="character_argon_female_01" class="npc">
  <properties>
    <boneroot name="Bip01" />
    <skeleton>
      <root name="bip01" />
      <head name="bip01 head" />          <!-- lookat 控制器 -->
      <righteye name="right_eye_dummy" /> <!-- lookat 控制器 -->
      <lefteye  name="left_eye_dummy" />
      <righthand name="attachment_helper" />
    </skeleton>
    <animations> ... 1100+ 条共享动画 ... </animations>
  </properties>
</component>
```

**这就是可行性的根基**：动画、骨骼根、注视控制器全部挂在共享 component 上，
macro 只负责挑模型。所以替换外观不会破坏动画系统。

### 2.2 参考 mod 实际改了什么（仅 3 个 XML）

1. **`libraries/charactergroups.xml`** — 把 2B 加进 4 个 Argon 女性外观池
   （service / marine / pilot / commander）：

   ```xml
   <add sel="/characters/character[@name='argon.pilot.female']">
     <select macro="character_argon_female_2b_macro"/>
   </add>
   ```

2. **`libraries/character_macros.xml`** — 定义新 macro，继承原版 base macro，
   只覆盖三个槽位；同时改玩家自定义开局的模型：

   ```xml
   <macro name="character_argon_female_2b_macro" class="npc"
          ref="character_argon_female_cau_base_01_macro">
     <component ref="character_argon_female_01" />
     <properties><models>
       <model type="head"  ref="extensions/x4_2b_mod/assets/characters/argon/heads/2b_head" />
       <model type="torso" ref="extensions/x4_2b_mod/assets/characters/argon/bodies/2b_body" />
       <model type="props" ref="none" />
     </models></properties>
   </macro>
   ```

3. **`libraries/material_library.xml`** — 新增 `2b` collection（11 个 material），
   每个 material 用 `p1_character` / `p1_hair` 着色器绑定 diffuse / normal / smooth 贴图。

### 2.3 命名映射规则（重要）

XAC 内部的材质槽名直接决定材质解析：

| XAC 网格节点名 | → collection | → material |
|---|---|---|
| `2b.skin` | `2b` | `skin` |
| `2b.whiteclothes` | `2b` | `whiteclothes` |
| `2b.blackclothes` | `2b` | `blackclothes` |
| `2b.head` / `2b.hair1` / `2b.hair2` … | `2b` | `head` / `hair1` / `hair2` … |

即 **`<collection>.<material>`**，与 `material_library.xml` 的 `name` 属性对应。
一个 XAC 可以带 100+ 个材质槽（原版躯干就带了一堆未使用的），
游戏只解析实际被网格引用的那几个。

## 三、决定性验证：骨骼兼容性

### 3.1 XAC 格式（已实测解析）

```
0x00  4   magic "XAC "
0x04  4   version = 0x01000001
0x08  24  header 字段
0x28  ..  头部字符串（带 u32 长度前缀）：
            +0x00 导出器标签  "X4CharacterConverter v0.8.7"
            +0x1b 源工程文件名 "char_arg_f_dyn_blend_head_rerig.xac"
            +0x45 导出日期    "2026-09-14"
之后     名称表：每条 = u32 长度 | ASCII 名 | 修正字节 | 节点数据
         顺序固定为：骨骼 → 网格对象 → 材质
之后     网格载荷（索引 + 顶点）
```

**最有力的取证**：XAC 头部记录了**源工程文件名**。
参考 mod 的两个文件分别写着：

- `2b_head.xac` ← 源文件 `char_arg_f_dyn_blend_head_rerig.xac`
- `2b_body.xac` ← 源文件 `char_arg_f_sweater_leggings_civ_01_no_skirt.xac`

后缀 `_rerig`（重新绑定骨骼）和 `_no_skirt`（去掉裙子）直接说明了做法：
**拿原版资产重绑骨骼后替换网格**，而不是从零转换。

### 3.2 逐字节比对结果

用 `tools/xac.py` 对「原版基准 vs 2B」执行骨架比对：

**头部**（基准 `char_arg_f_dyn_blend_head.xac`）：

```
vanilla skeleton : 91 bones x 1 copies = 91 entries
mod bones        : 91 entries (align offset 0)
bone names       : IDENTICAL
bind payloads    : 91/91 byte-identical
VERDICT          : COMPATIBLE
```

**躯干**（基准 `char_arg_f_sweater_leggings_civ_01.xac`）：

```
vanilla skeleton : 91 bones x 4 copies = 364 entries
mod bones        : 91 entries (align offset 0)
bone names       : IDENTICAL
bind payloads    : 91/91 byte-identical
VERDICT          : COMPATIBLE
```

> **注意**：原版躯干里整套 91 骨骼骨架重复了 **4 次**（364 = 4×91，源 .max 合并所致）。
> 按名字去重的比较器会静默吞掉这些副本并给出错误结论 —— 比对必须保序。

### 3.3 91 根骨骼的构成

```
Bip01 …                          标准 3ds Max Biped 骨架
  Pelvis / Spine / Spine1 / Spine2 / Neck / Head / HeadNub
  {L,R} Clavicle / UpperArm / Forearm / Hand
  Finger0..4 × {0,1,2,Nub}       五指完整骨链
  {L,R} Thigh / Calf / Foot / Toe0 / Toe0Nub
left_eye_dummy / right_eye_dummy 注视控制器（游戏读这个）
Attachment_Helper                手持物挂点
{L,R}_Elbow_{front,back}_Helper  变形辅助骨
{L,R}_Delt_Helper / {L,R}_Pec_{Helper,LookAt}
{L,R}_Lat_Helper / {L,R}_Knee_* / {L,R}_Glute_Helper
{L,R}_Hip_Helper / {L,R}_Quad_Helper
LookAt_Target
```

**含义**：这是一套标准的 3ds Max Biped 骨架，骨骼名语义清晰。
任何建模工具只要能导出/匹配这套骨骼名，就能做 NPC 替换。
面部/语音口型（`Ter_f_cau.phon_*`、`Ter_f_cau.mt_*`）在名称表里是
**材质槽名**而非骨骼 —— 这点容易误判。

## 四、面部外观（facemods）机制与注意事项

`character_argon_female_cau_base_01_macro` 里有 **50 条 `facemod`**：

```xml
<facemod type="nose_size" name="Ter_f_cau.mt_nose_size" min="-1" max="1" />
<facemod type="age"       name="Ter_f_cau.mt_age"        min="0" max="1" profile="decreasing"/>
```

配合 `<bonemod type="Head" exact="0.9">`，这是 X4 的**程序化捏脸系统**：
玩家的「自定义开局」会随机化这些参数来生成独一无二的面孔。

参考 mod 的做法是**不写 facemods**（继承基类），把 2B 做成固定外观，
且 `select macro=` 的方式让它在 NPC 池里作为一个确定外观出现。

**风险点（需实机确认）**：玩家自定义开局（`character_player_custom_f_cau_macro`）
被 mod 直接替换了 head/torso 模型，但捏脸参数仍会作用于新模型。
若实机发现玩家角色面部畸变，需要在 macro 里显式重置 facemods 的 min/max。

| `texconv.dll`（RE-Mesh-Editor 内置） | PNG → DDS（BC1/3/4/5） | ✅ 具备 |

### 5.1 导出器的工作模型（重要）

`X4CharacterConverter` **不是从零导出**，而是「**导入原版 XAC → Blender 里改 → 原地重建**」：

- `xac_format.export_xac()` 只做原地编辑（改位置/材质ID/权重），顶点数不能变；
- `body_format.rebuild_actor()` 则**重建网格**，允许改拓扑。
- 导出包（`export_package`）会一并产出 `.xac` + `.dds.gz` 贴图 + `material_library.xml`。

因此宿主必须是一个**原版 XAC**，其骨架被完整继承。

### 5.2 导出器的硬约束

| 约束 | 要求 |
|---|---|
| 材质名 | `<collection>.<material>`，仅小写字母/数字/下划线 |
| 贴图节点名 | `Diffuse`(必需) / `Normal` / `Metal` / `Smoothness` / `Glow` |
| 贴图格式 | 必须 **DDS**；Diffuse=BC1/BC3，Normal=BC5，Metal/Smoothness=BC4 |
| 偏好设置 | 必须指定「Unpacked X4 Root」（解包的游戏根目录） |

> RE8 的 `NRMR` 贴图是「RGB=法线 / A=粗糙度」打包格式，需要**拆成两张 DDS**：
> → `Normal`(BC5) + `Smoothness`(BC4，粗糙度取反)。

## 六、实机验证建议

技术链路已在文件层闭环，剩下的唯一不确定项是**引擎内的实际表现**。
推荐的最小实机验证：

1. 把 `x4_2b_mod` 复制到 `X4 Foundations\extensions\`（当前**未安装**）
2. 启动游戏 → 新建/读取存档 → 招募 Argon 女性船员/飞行员
3. 检查项：模型是否显示、骨架是否跟随动画、材质是否正确、面部是否畸变

> 制作自己的 mod 时，用 `-buildcat` 把资产打成 `ext_01.cat` 是官方推荐做法
> （见 X Tools Readme：「ext_* catalogs 是推荐的改游戏方式，兼容性最好」）。
